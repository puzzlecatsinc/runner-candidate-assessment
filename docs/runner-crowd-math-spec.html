Runner Crowd Math: Testable + Safer Gate Rules

Living spec for the focused fix: extract deterministic crowd-count rules from Unity scene side effects, cover the edge cases with EditMode tests, and wire the existing game loop through one clean rule path.

Problem

PlayerController.cs currently owns both deterministic count math and Unity scene effects. That makes gate behavior hard to test and easy to regress.

Concrete bug: DivideCharacters kills a one-runner crowd before calculating the divide result. For a non-lethal divide gate, 1 / n should clamp to one, not kill the player.

Goal

Introduce a small pure C# rule layer for crowd count transitions, then have the runtime methods call that rule layer. Keep the existing public methods and scene side effects.

Small refactor No asset churn No fallback path

Non-goals

  • No broad Unity/game architecture rewrite.
  • No prefab, scene, material, shader, or third-party package edits unless absolutely required.
  • No generated Unity cache/build/IDE files in submission.

Functional requirements

  • Add positive runners up to MaxCrowd.
  • Add negative runners by removing runners, never accidentally underflowing.
  • Negative add that removes the final runner is intentionally lethal.
  • Multiply clamps to MaxCrowd.
  • Divide floors, clamps non-lethal outcomes to at least one, and treats invalid divisors deliberately.
  • Existing UI/audio/FOV/death side effects still fire when runtime count actually changes or dies.

Recommended design

public enum CrowdCountOutcomeType { NoOp, Changed, Dead }

public readonly struct CrowdCountOutcome {
    public int TargetCount { get; }
    public CrowdCountOutcomeType OutcomeType { get; }
}

public static class CrowdCountCalculator {
    public static CrowdCountOutcome Add(int current, int amount, int max);
    public static CrowdCountOutcome Multiply(int current, int multiplier, int max);
    public static CrowdCountOutcome Divide(int current, int divisor, int max);
}
